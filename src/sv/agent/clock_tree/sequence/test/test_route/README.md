## 细节

### 使用者视角

验证站在使用者角度，只看最终输出的时钟频率和有效性。只要最终输出符合预期，中间结构的等价变化不作为错误。

忽略场景：

- 两个 **gate** 串联。
- **gate** 与 **div** 串联。
- **gate** 与 **dto** 串联。

### 路线形状

对某个节点，切换下游 **gate**、**mux**、**div**、**dto** 等配置，计算输出时钟频率和有效性，并按预期值检查。

一条线上有多个节点串联时，对这些节点的配置做排列组合。

所有组合均正确时，说明这个节点的下游路线形状符合预期。

上游路线按同样方式排列组合，此时下游需要保证时钟均有效。

每个节点的上游、下游形状均正确时，拼接结果只有唯一解，整棵时钟树的形状正确。

### 输入不同频率

为了避免 `mux` 切换时两路时钟频率相同，需要制造输入时钟频率每一路都不同。

将晶振作为最低输入频率，参与倍数分配的各 **pll** 频率分别固定为晶振的 N 倍、N+1 倍……，N 为不小于 2 且全体 **pll** 均可配置的最小整数。

### 分频测试

为了提高测试效率，即提高时钟频率，分频系数平时会固定为1，在切换时也只在1和2之间切换，尽可能减小频率损耗。

### 不参与测试的节点

有的节点不参与测试，它当前选中的路径上所有器件也都不参与测试，含路径上的 **pll**，其频率保持首次 **config_reg** 后的值不变。
