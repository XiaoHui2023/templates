# flip_check

在器件输入端施加独立激励，检查寄存器控制下的器件输出功能。tree 必须已经 build，候选器件需要完整接口和寄存器绑定。

## req

| 成员 | 类型 | 说明 |
| --- | --- | --- |
| **tree** | **tree_base** | 时钟树 |
| **quiet** | **bit** | 隐藏开始和汇总信息 |
| **debug** | **bit** | 强制打印开始信息 |

## 流程

1. 校验请求和 tree，执行一次 low_power 配置。
2. 收集 stable 时钟及其结构上游，筛除这些器件和无有效时钟下游的控制器件。
3. 按候选顺序逐个测试器件。
4. 在当前器件输入端施加固定激励，配置寄存器，再测量或采样输出。
5. 释放当前器件输入驱动后测试下一个器件，最后汇总结果。

## 设计

### 器件检查

| 器件 | 检查内容 |
| --- | --- |
| **gate** | 100 MHz 输入下分别检查打开有频率、关闭无活动 |
| **div** | 800 MHz 输入和 ratio 4 下检查 200 MHz 输出 |
| **dto** | 800 MHz 输入和 ratio 4 下检查 200 MHz 输出 |
| **mux** | 各输入使用不同频率，遍历全部选择值并核对输出频率 |
| **inv** | 按 **inv_reg_high_means_inverted** 极性遍历直通、反相配置和输入 0/1 |

**div/dto** 使用代表 ratio 验证功能，不穷举寄存器全部取值。PLL 不做功能检查，每个 PLL 打印 skip。

频率激励按期望值生成；活动检测下限取期望频率减去允许误差。最低频率只控制等待时限，不参与周期样本筛选。

### 串行与寄存器

器件严格串行测试。当前器件的寄存器配置、激励、测量和清理全部完成后，才测试下一个器件，避免寄存器事务或结构信号相互干扰。与 stable 支路共用控制字段的器件直接跳过。

### 跳过、清理与错误

每个候选器件固定打印一次 **test** 或 **skip**，不打印寄存器逐值翻转过程。stable 时钟上游、无效控制器件、缺接口或缺寄存器的器件跳过并打印原因。任一器件没有产生唯一的 check/skip 状态时终止 operation。器件错误使用 **UVM_ERROR** 累计，释放当前输入后继续；请求、tree、工具无效或没有可用候选时同样终止 operation。
