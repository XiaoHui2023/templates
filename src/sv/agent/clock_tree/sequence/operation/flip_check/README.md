# flip_check

在器件输入端施加独立激励，检查寄存器控制下的器件输出功能。tree 必须已经 build，候选器件需要完整接口和寄存器绑定。

## req

| 成员 | 类型 | 说明 |
| --- | --- | --- |
| **tree** | **tree_base** | 时钟树 |
| **quiet** | **bit** | 静默打印 |
| **debug** | **bit** | 强制打印开始信息 |

## 流程

1. 校验请求和 tree，执行一次 low_power 配置。
2. 收集 stable 时钟及其结构上游，筛除这些器件和无有效时钟下游的控制器件。
3. 并行启动全部候选器件检查；每个并行任务在创建时固定循环索引。
4. 每个并行任务在当前器件输入端施加固定激励，串行写该器件寄存器，测量或采样输出。
5. 完成当前器件全部检查后释放输入驱动。
6. 全部并行任务完成后汇总实际检查数、跳过数和失败数。

## 设计

### 器件检查

| 器件 | 检查内容 |
| --- | --- |
| **gate** | 100 MHz 输入下分别检查打开有频率、关闭无活动 |
| **div** | 800 MHz 输入和 ratio 4 下检查 200 MHz 输出 |
| **dto** | 800 MHz 输入和 ratio 4 下检查 200 MHz 输出 |
| **mux** | 各输入使用不同频率，遍历全部选择值并核对输出频率 |
| **inv** | 遍历直通、反相配置和输入 0/1 |

**div/dto** 使用代表 ratio 验证功能，不穷举寄存器全部取值。PLL 不做功能检查。

### 并发与寄存器

不同器件的激励、等待和测量并行；共享寄存器访问通过一个 semaphore 串行。并行只减少等待时间，不允许并发访问寄存器总线。

### 跳过、清理与错误

stable 时钟上游、无效控制器件、缺接口或缺寄存器的器件跳过并打印原因。器件错误使用 **UVM_ERROR** 累计，释放当前输入后继续；请求、tree、工具无效或没有可用候选时终止 operation。

## rsp

| 成员 | 类型 | 说明 |
| --- | --- | --- |
| **ok** | **bit** | 全部已检查器件通过 |
| **failed** | **int** | 失败检查数 |
