# flip_check

在器件输入端施加独立激励，检查寄存器控制下的器件输出功能。tree 必须已经 build，候选器件需要完整接口和寄存器绑定。

## req

| 成员 | 类型 | 说明 |
| --- | --- | --- |
| **tree** | **tree_base** | 时钟树 |
| **quiet** | **bit** | 隐藏开始和汇总信息 |
| **debug** | **bit** | 强制打印开始信息 |

## 流程

1. 校验请求和 tree，执行一次 low_power 配置。
2. 收集 stable 时钟及其结构上游，筛除这些器件和无有效时钟下游的控制器件。
3. 根据输入驱动和输出观测的结构信号冲突，将候选器件划分为多个批次。
4. 各批依次执行；批内器件并行启动，每个任务在创建时固定循环索引。
5. 每个任务在当前器件输入端施加固定激励，在寄存器 semaphore 内配置当前器件，再测量或采样输出。
6. 完成当前器件全部检查后释放输入驱动；全部批次完成后汇总结果。

## 设计

### 器件检查

| 器件 | 检查内容 |
| --- | --- |
| **gate** | 100 MHz 输入下分别检查打开有频率、关闭无活动 |
| **div** | 800 MHz 输入和 ratio 4 下检查 200 MHz 输出 |
| **dto** | 800 MHz 输入和 ratio 4 下检查 200 MHz 输出 |
| **mux** | 各输入使用不同频率，遍历全部选择值并核对输出频率 |
| **inv** | 按 **inv_reg_high_means_inverted** 极性遍历直通、反相配置和输入 0/1 |

**div/dto** 使用代表 ratio 验证功能，不穷举寄存器全部取值。PLL 不做功能检查，每个 PLL 打印 skip。

### 并发与寄存器

两个器件共享同一输入源时，其输入可能属于同一条 RTL net；两个器件互为直接上下游时，一方输入驱动也可能影响另一方输出观测。这两类器件不得进入同一批。first-fit 按候选顺序组成批内无冲突的批次，各批串行、批内并行。

寄存器 semaphore 包住完整的单节点配置调用，防止两个线程的 read-modify-write 相互覆盖；激励、等待和测量不持锁。批内专用父进程用 **wait fork** 等待全部任务自然完成，不使用会提前终止任务的 **disable fork**。

### 跳过、清理与错误

每个候选器件固定打印一次 **test** 或 **skip**，不打印寄存器逐值翻转过程。stable 时钟上游、无效控制器件、缺接口或缺寄存器的器件跳过并打印原因。任一并行任务没有产生唯一的 check/skip 状态时终止 operation，不能由其它成功项掩盖。器件错误使用 **UVM_ERROR** 累计，释放当前输入后继续；请求、tree、工具无效或没有可用候选时同样终止 operation。
