# flip_check

串行执行节点插件提供的功能检查，tree 必须完成 build。

## req

| 成员 | 类型 | 说明 |
| --- | --- | --- |
| `tree` | `tree_base` | 时钟树 |

## 流程

1. 应用低功耗偏好并执行一次寄存器配置。
2. 遍历 `tree.nodes`，选择 `has_functional_contract()` 为真的节点。
3. 跳过 `_should_check` 为假的节点、stable 节点及其上游、与受保护节点共用控制字段的节点，以及不满足下游测量要求的节点。
4. 逐个调用 `run_functional_contract()`，由插件完成激励、寄存器切换、输出检查和驱动释放。
5. 汇总检查、跳过和失败结果。

## 设计

### 插件覆盖

| 节点 | 检查内容 |
| --- | --- |
| gate | 1 GHz 输入下检查打开输出为 1 GHz、占空比合格，关闭无活动 |
| div | 按绑定寄存器位宽逐 bit 写 one-hot 编码，检查输出频率和占空比 |
| dto | 检查旁通，每个 step 位分别写 0、1，按实际 step 计算平均输出频率；不检查占空比 |
| clk_div_with_clken | 遍历全部 16 种编码，检查三个输出频率；全部输出不检查占空比 |
| mux | 遍历输入选择并检查频率、占空比；独立输入使用不同频率，原生输入保留实际时钟 |
| inv | 遍历极性配置，检查输入高低电平及 1 GHz 输出的频率、占空比 |

- div 每次写分频值前复位，再写分频值和 load；某一位对应的频率低于测量下限时，该位记为失败。
- div、dto 配置后等待稳定，inv 写极性后等待再采样；等待时间和寄存器极性由插件设置决定。
- dto 与普通配置共用写入流程：step、bypass 在 load 上升前写入，复位和 load 变化保留同步等待，再开始输出测量。
- dto 的 step 测试采用高位保持加逐位变化，不遍历全部数值；频率按 `输入频率 × step / 2^25` 比较。检查每位被写成过 0、1，不代表在当前频率容差下能分辨每个低位的单独故障。
- dto 的相邻周期允许累加器量化抖动，使用多周期平均频率；测量窗口和超时同步扩大，不放宽频率容差。
- mux 写选择值后等待 70 ns。

### 输出测量

插件调用基础节点的 `check_output()`，解析输出策略后交给 `node_test_api` 检查活动、频率稳定及数值误差、占空比。频率不符和占空比不符分别报告；关闭占空比检查不会关闭频率检查。

`output_duty_check_enabled(key)` 默认开启，插件可按输出端口关闭。`output_frequency_window(key)` 默认 1 周期，插件可声明平均窗口。窗口只影响频率，不能掩盖占空比错误。普通 `check_measure` 的端点选择仍由 `supports_duty_observation()` 决定。

### 驱动与错误

节点检查期间保持输入 force，全部检查结束后释放，再测试下一个节点。节点失败会累计并继续；缺接口或寄存器绑定由插件打印原因并跳过。

插件必须返回唯一的检查或跳过状态。全部被 `_should_check` 或 stable 保护跳过时允许返回；没有功能检查节点或其余筛选条件造成无候选时终止。请求、tree、工具无效时终止。
