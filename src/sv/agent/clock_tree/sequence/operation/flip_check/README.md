# flip_check

串行执行节点插件提供的功能检查，tree 必须完成 build。

## req

| 成员 | 类型 | 说明 |
| --- | --- | --- |
| `tree` | `tree_base` | 时钟树 |
| `quiet` | `bit` | 隐藏开始和汇总信息 |
| `debug` | `bit` | 强制打印开始信息 |

## 流程

1. 应用低功耗偏好并执行一次寄存器配置。
2. 遍历 `tree.nodes`，选择 `has_functional_contract()` 为真的节点。
3. 跳过 `_should_check` 为假的节点、stable 节点及其上游、与受保护节点共用控制字段的节点，以及不满足下游测量要求的节点。
4. 逐个调用 `run_functional_contract()`，由插件完成激励、寄存器切换、输出检查和驱动释放。
5. 汇总检查、跳过和失败结果。

## 设计

### 插件覆盖

| 节点 | 检查内容 |
| --- | --- |
| gate | 1 GHz 输入下检查打开有时钟、关闭无活动 |
| div | 按绑定寄存器位宽逐 bit 写 one-hot 编码，检查输出频率 |
| dto | 用分频比 4 检查 1 GHz 输入对应的 250 MHz 输出 |
| mux | 遍历输入选择；独立输入使用不同频率，原生输入保留实际时钟 |
| inv | 遍历极性配置，检查输入 0、1 对应的输出 |

div 每次写分频值前复位，再写分频值和 load；某一位对应的频率低于测量下限时，该位记为失败。div、dto 配置后等待稳定，inv 写极性后等待再采样；等待时间和寄存器极性由插件设置决定。mux 写选择值后等待 70 ns。

### 驱动与错误

节点检查期间保持输入 force，全部检查结束后释放，再测试下一个节点。节点失败会累计并继续；缺接口或寄存器绑定由插件打印原因并跳过。

插件必须返回唯一的检查或跳过状态。全部被 `_should_check` 或 stable 保护跳过时允许返回；没有功能检查节点或其余筛选条件造成无候选时终止。请求、tree、工具无效时终止。
